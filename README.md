# Secretary Bot — auto-reply + self-learning FAQ

## Що робить

- Відповідає в бізнес-чатах (Telegram Business "Автоматизація чатів") на вхідні повідомлення.
- Спершу питає локальну Ollama, чи є впевнена відповідь на основі бази FAQ.
- Якщо AI не впевнена — падає назад на заглушку "адміна нема на місці", текст якої залежить від години доби (з cooldown в 1 годину на користувача).
- Логує **всю** переписку (і клієнта, і адміна) в `data/conversation-log.jsonl`.
- Раз на добу (за розкладом cron) прогонює лог через Ollama, щоб знайти повторювані типові питання і відповіді адміна на них.
- Нові кандидати не додаються в базу автоматично — вони йдуть у чергу `data/faq-pending.json`, і адмін підтверджує/відхиляє їх командами в Telegram.

## Встановлення

```bash
cd secretary-bot
npm install
cp .env.example .env
# заповни .env: BOT_TOKEN, ADMIN_TELEGRAM_ID
```

Переконайся, що Ollama встановлена і запущена (`systemctl status ollama`), і модель з `config/ollama-config.json` (`chatModel`/`analysisModel`) завантажена (`ollama pull qwen2.5:7b`).

Запуск (напряму або через PM2, як інші твої проєкти):

```bash
node bot.js
# або
pm2 start bot.js --name secretary-bot
```

## Структура

```
bot.js                      — точка входу, вся обробка апдейтів
config/
  auto-reply-config.json    — тексти заглушок за годинами, cooldown, таймзона
  ollama-config.json        — URL Ollama, моделі, таймаути, базові промпти
data/
  conversation-log.jsonl    — сирий лог переписки (append-only)
  faq-knowledge.json        — підтверджені пари питання/відповідь
  faq-pending.json          — кандидати, що очікують підтвердження
lib/
  storage.js                — читання/запис JSON з захистом від гонки записів
  conversationLogger.js     — логування + базова редакція чутливих даних
  ollama.js                 — виклики до Ollama (чат-відповідь + аналіз логу)
  faq.js                    — керування FAQ/чергою кандидатів, побудова системного промпту
  autoReply.js              — вибір тексту заглушки за годиною
cron/
  dailyFaqAnalysis.js       — задача аналізу денного логу
```

## Команди адміна (пиши боту напряму, не в бізнес-чаті)

- `/pending` — показати всіх кандидатів у черзі
- `/approve_<id>` — підтвердити кандидата, додати в FAQ
- `/reject_<id>` — відхилити кандидата
- `/analyze_now` — запустити аналіз логу за останню добу вручну (не чекаючи cron)

## Налаштування

- **Розклад заглушок** — редагуй `config/auto-reply-config.json`, зміни підхоплюються без рестарту.
- **Промпти для AI** — `config/ollama-config.json`, поля `baseSystemPrompt` (чат-відповіді) і `analysisSystemPrompt` (аналіз логу).
- **Час щоденного аналізу** — змінна `DAILY_ANALYSIS_CRON` в `.env` (формат cron, за замовчуванням `50 23 * * *` — 23:50 щодня).
- **Приватність** — `lib/conversationLogger.js` вирізає довгі числові послідовності (номери карток/договорів/телефонів) та email перед тим, як текст піде в модель для аналізу. Це базовий фільтр, не 100% гарантія — за потреби розширюй `redactSensitive()`.

## Важливі нюанси

- Дані повністю залишаються на твоєму сервері (Ollama локальна), в зовнішні сервіси нічого не йде.
- Кандидати в FAQ ніколи не публікуються автоматично — тільки через явне `/approve_<id>`.
- Якщо Ollama недоступна або відповідає довше за таймаут — бот тихо falls back на заглушку за годиною, без падіння.
